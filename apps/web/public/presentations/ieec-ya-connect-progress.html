Why this exists

The problem we are solving

Before

  • Newcomer follow-up scattered across chats and sheets
  • Hard to see who is assigned and what is overdue
  • Roles and permissions unclear
  • Web, phone, and data not connected

Goal

  • Every newcomer contacted and cared for
  • Clear ownership: queue → assign → report
  • Leaders see progress; ministers work their list
  • Same live data on phone and browser

Platform strategy

Can both be primary? Yes.

Mobile and web are co-primary — same product, different strengths. Not “mobile only” or “web only.”

Mobile (iOS + Android)

  • Primary for ministers in the field
  • Quick assign views, reports, reminders
  • Notifications on the go
  • Expo → TestFlight / App Store / Play

Web

  • Primary for public registration & church site
  • Primary for leaders on larger screens (queue, RBAC, review)
  • Admin / CMS and stakeholder demos
  • Deploys continuously (Vercel for now)

One GitHub monorepo + one Firebase. A Follow-Up rule change in shared logic helps both; UI still ships per client.

Follow-Up workflow · detail

1 · Registration → queue

  1. 1Newcomer registers via public web form (no login), QR link, or future mobile/internal form. Captures name, contact, language, first visit, how heard, prayer, consent.
  2. 2Duplicate check — system flags possible matches; leaders review (no silent auto-merge).
  3. 3Person + journey created — ministry status = Newcomer; audit logged.
  4. 4Leaders notified — Team Leader & Assistant see a new unassigned item.
  5. 5Enters unassigned queue — waiting for a Follow-Up minister.

Follow-Up workflow · detail

2 · Assign → first contact

  1. 6Leader / Assistant assigns a primary minister (optional secondary). Card-style picker; reason and dates recorded.
  2. 7Assignee notified — push/in-app so the minister knows immediately.
  3. 8First follow-up deadline calculated so nobody sits forgotten.
  4. 9Reassignment allowed — history kept; prior work is not erased.
  5. 10Assignment statuses — pending, active, paused, reassigned, completed, cancelled.

Follow-Up workflow · detail

3 · Care loop (minister week)

What ministers do

  • Open assigned people list
  • Call / text / meet / WhatsApp
  • Log a weekly follow-up report
  • Record method, outcome, summary
  • Note prayer, needs, spiritual progress
  • Set next action + date
  • Escalate concerns when needed

Alongside the report

  • Attendance tracked separately (service/event presence)
  • Bio / notes for ongoing context
  • Team notes & tasks for shared checklist work
  • Calendar for planned contacts / events
  • Chat for team coordination (not a substitute for the report)

Follow-Up workflow · detail

4 · Leadership visibility & transition

Leaders / Assistants

  • See all newcomers & queue health
  • Spot overdue follow-ups
  • Reassign when load or fit is wrong
  • Review reports and escalations
  • Manage roles & permissions (RBAC)
  • Recommend or approve status changes

Journey outcomes

  • Continue active Follow-Up
  • Pause temporarily (with reason)
  • Close / complete pathway
  • Reopen if they return
  • Transition toward membership when ready
  • Every sensitive change audited
Register→ Queue→ Assign→ Contact + report→ Review→ Transition

Follow-Up workflow · roles

Who does what

Team Leader

Full queue, assign/reassign, records, overdue review, team membership, reports, configure rules when allowed.

Assistant Leader

View all, assign/reassign, create/update follow-up records, support leader, notify when permitted.

Follow-Up Minister

Own assigned newcomers only; log updates, needs, attendance, next steps; receive reminders; escalate.
