Why this exists

The problem we are solving

Before

  • Newcomer follow-up scattered across chats and sheets
  • Hard to see who is assigned and what is overdue
  • Roles and permissions unclear
  • Web, phone, and data not connected

Goal

  • One people-centered Follow-Up system
  • Clear queue → assign → report loop
  • Role-based access for leaders & ministers
  • Same data on web, iOS, and Android

How we work

Delivery workflow

You describe need → Agent builds in GitHub → Pull request review → Merge → Web deploys (Vercel)

You do not need to code

Request changes in plain language. Review the result. Approve merge when ready.

One codebase

GitHub monorepo holds web, mobile starter, shared rules, Firebase config, and docs.

Architecture

One repo, three layers

apps/web

Public site + staff Follow-Up CMS (React). Live path via Vercel for now.

apps/mobile

Expo (React Native) starter for iOS & Android. Same product, native shells.

packages/shared + Firebase

Shared types & RBAC. Auth + Firestore as the production backend target.

Data changes sync across platforms once they share Firebase. App UI updates still ship per client.

Platforms

Web vs mobile today

Web — primary

Most Follow-Up product work lives here. Deployed for demos via Vercel (temporary hosting choice).

Mobile — scaffolded

Expo app exists for iOS + Android. Not full Follow-Up parity yet. Store release comes after feature parity + TestFlight.

One change request can cover all platforms when both clients are built — shared logic first, then each UI.

End-to-end picture

Ministry workflow we support

Visit / hear about YA → Register online → Enter Follow-Up queue → Leader assigns → Minister follows up → Report & next step

Leaders

See the queue, balance load, manage roles, stay notified.

Ministers

Work assigned people, log contact, keep notes and tasks together.
